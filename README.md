# 허재혁

**저장한 생각은 왜 다시 보지 않을까? 고객의 불편은 무엇부터 고쳐야 할까? 숫자가 바뀌었을 때 무엇을 실행해야 할까?**

이런 질문을 서비스, 분석 도구, 운영 화면과 콘텐츠로 만들어 확인합니다. 각 결과물에는 출발한 문제와 실제로 확인한 범위를 함께 남깁니다.

## 질문에서 시작한 결과물

### 기록과 정보는 어떻게 다시 쓰이나

- [MEMOIVE](https://github.com/jhheo51-arch/memoive): 저장한 자료에 생각을 붙이고 다시 꺼내 쓰는 기록 서비스입니다.
- [새록이](https://github.com/jhheo51-arch/saeroki): 질문에 맞는 자료를 찾고 출처와 근거를 확인하는 개인 에이전트 프로젝트입니다.

### 고객은 어디에서 막히나

- [VoC Lens](https://github.com/jhheo51-arch/VoC-Lens): 리뷰, 상담 음성과 영상에서 고객의 불편을 찾아 개선 과제의 순서를 제시합니다.
- [Aurora Owners 360](https://github.com/jhheo51-arch/aurora-owners-360): 가상 전기차 고객센터의 차주와 차량 기록을 연결하고 안전 VOC 이관 규칙을 구현했습니다.
- [헤이딜러 CX](https://github.com/jhheo51-arch/heydealer-cx): 공개 리뷰에서 구매 뒤 연락 공백의 가설을 찾고 응대 절차를 제안했습니다.
- [NEXT CUP](https://github.com/jhheo51-arch/next-cup-ai-portfolio): 좋아했던 음료의 특징으로 다음 선택을 돕고, 조건에 맞지 않으면 추천을 보류하는 시제품입니다.

### 운영자는 무엇을 먼저 해야 하나

- [셀러 레디 보드](https://github.com/jhheo51-arch/baemin-store-seller-ready-board): 판매 준비의 정보 오류와 담당자 누락을 먼저 볼 수 있게 한 가상 운영 보드입니다.
- [권역별 운영 실험 보드](https://github.com/jhheo51-arch/regional-ops-experiment-board): 배달 지연의 원인 가설을 비교하고 현장 확인과 조치 전후 결과를 기록하도록 설계했습니다.
- [백화점 아침 점검 에이전트](https://github.com/jhheo51-arch/dept-morning-brief): 가상 운영 자료와 공개 정보를 묶어 마케팅 담당자의 아침 점검을 한 장으로 보여 줍니다.
- [claim-relay](https://github.com/jhheo51-arch/claim-relay): 가상 사고 청구에서 규칙으로 심사 경로를 정하고 불확실한 건은 사람에게 넘깁니다.

### 데이터는 어떤 실행을 바꾸나

- [CRM LOOP](https://github.com/jhheo51-arch/crm-loop): 공개 거래 기록으로 재방문 대상 후보를 고르고 캠페인 효과의 비교 방법을 설계했습니다.
- [IRP 계좌 성장 레이더](https://github.com/jhheo51-arch/irp-growth-radar): 공시와 앱 리뷰를 대조해 가입 이후 막히는 단계를 찾고 개선 순서를 제안했습니다.
- [여의도 유동 분석](https://github.com/jhheo51-arch/yeouido-footfall): 역 승하차와 날씨 자료로 시기별 유동 차이를 읽고 적용 범위를 밝혔습니다.
- [A/B 실험 노트](./portfolio/salesforce-mc-crm/service_revisit_demo/): 합성 자료에서 방문 완료율을 비교하고 전면 적용을 보류한 이유를 기록했습니다.

### 발견한 것을 어떻게 전하나

- [Trend to Trust](https://github.com/jhheo51-arch/trend-to-trust): 공개 트렌드를 카드뉴스로 옮기고 익명 반응을 바탕으로 문장을 수정했습니다.

## 일하는 방식

1. **문제를 좁힙니다.** 누가 어떤 상황에서 막히는지 먼저 적습니다.
2. **판단 기준을 세웁니다.** 무엇을 보고 진행하거나 멈출지 실행 전에 정합니다.
3. **작게 만들어 봅니다.** 화면, 코드와 업무 규칙으로 옮겨 실제 입력을 넣고 확인합니다.
4. **결과의 범위를 밝힙니다.** 공개 자료 분석, 가상 구현, 합성 실습과 실제 사용자 결과를 구분합니다.
