# 허재혁의 작업실

**막히는 지점을 찾으면, 직접 써볼 수 있는 형태로 만듭니다.**

고객 경험, 정보 탐색, 운영과 기록의 문제를 다룹니다. 결과물의 형태는 서비스 화면, AI 도구, 데이터 분석, 실험 노트, 콘텐츠와 문서로 다양합니다. 무엇을 만들었는지와 함께 판단을 바꾼 이유, 아직 검증하지 못한 부분을 남깁니다.

## 작업대에 놓인 결과물

### 서비스와 시스템

- [MEMOIVE](https://github.com/jhheo51-arch/memoive): 저장한 자료에 자신의 생각을 붙여 다시 찾아 쓰는 기록 서비스입니다.
- [Aurora Owners 360](https://github.com/jhheo51-arch/aurora-owners-360): 가상 전기차 고객센터의 기록과 안전 VOC 이관 규칙을 Salesforce에 구현했습니다.

### 에이전트와 도구

- [새록이](https://github.com/jhheo51-arch/saeroki): 질문에 필요한 자료를 찾고 답을 검토하는 개인 AI 에이전트를 설계했습니다.
- [VoC Lens](https://github.com/jhheo51-arch/VoC-Lens): 고객 의견을 분류하고 사람이 확인할 우선순위를 제시하는 도구입니다.

### 분석과 실험

- [CRM LOOP](https://github.com/jhheo51-arch/crm-loop): 공개 거래 기록으로 재방문 대상 후보를 고르고, 캠페인 효과를 비교할 방법을 설계했습니다.
- [A/B 실험 노트](./portfolio/salesforce-mc-crm/service_revisit_demo/): 합성 자료에서 안내 방식과 방문 완료를 비교했습니다. 고객 보호 지표의 악화 가능성을 배제하지 못해 전면 적용을 보류한 교육용 사례입니다.

### 콘텐츠

- [Trend to Trust](https://github.com/jhheo51-arch/trend-to-trust): 공개 트렌드를 콘텐츠 제작안으로 옮기고 반응을 바탕으로 수정했습니다.

## 일하는 방식

1. **문제를 좁힙니다.** 누가 어떤 상황에서 막히는지 먼저 적습니다.
2. **판단 기준을 세웁니다.** 무엇을 보고 진행하거나 멈출지 실행 전에 정합니다.
3. **작게 만들어 봅니다.** 화면, 코드와 업무 규칙으로 옮겨 실제 입력을 넣고 확인합니다.
4. **결과의 범위를 밝힙니다.** 공개 자료 분석, 가상 구현, 합성 실습과 실제 사용자 결과를 구분합니다.

코드 작성과 조사, 검사를 보조하는 도구로 Codex와 Claude Code를 사용합니다. 문제와 기능 범위, 최종 판단은 제가 정하고 결과를 검토합니다.
