# 허재혁 | 제품 기획과 운영

문제의 이유와 판단 기준을 정리하고, 이를 직접 확인할 수 있는 웹 서비스와 운영 도구로 만듭니다.

제품 기획, 데이터 분석과 운영 설계에 관심을 두고 프로젝트를 진행합니다. 공개 자료에서 확인한 사실, 제가 세운 가정과 아직 검증하지 못한 효과를 구분해 기록합니다.

## 작업하는 방식

- **문제부터 정리합니다.** 누가 어떤 순간에 막히는지와 무엇이 달라져야 하는지를 먼저 적습니다.
- **선택의 이유를 남깁니다.** 기능과 지표를 나열하는 데서 그치지 않고 우선순위, 제외한 범위와 판단 조건을 설명합니다.
- **작동하는 결과물로 확인합니다.** 기획을 화면, 운영표와 계산 코드로 옮기고 입력을 바꿨을 때의 동작을 검사합니다.
- **결과의 한계를 구분합니다.** 자동 검사, 가상 자료의 계산과 실제 이용자 효과를 같은 성과로 취급하지 않습니다.

각 저장소 README에 문제를 선택한 이유, 사용 흐름, 결과물과 검증 범위를 정리했습니다. 소개자료가 있는 프로젝트는 PDF를 먼저 읽고 Excel과 구현을 확인할 수 있습니다.

## 프로젝트를 볼 때

웹 서비스에서는 직접 작성과 AI 보조의 역할, 저장 실패와 오류 이후의 흐름을 중점적으로 봤습니다. 운영 프로젝트에서는 담당자, 기한, 다음 행동과 완료 기준이 이어지는지를 확인했습니다.

코드 작성과 조사, 검사를 보조하는 도구로 Codex를 사용합니다. 프로젝트의 문제, 기능 범위와 최종 판단은 제가 정하고 결과를 검토합니다. 가상 고객과 시제품의 결과를 실제 회사의 운영 경험이나 성과로 제시하지 않습니다.

## 질문과 제안

프로젝트 관련 질문은 해당 공개 저장소의 **Issues(질문과 개선 제안을 남기는 공간)**에서 다룹니다.

대표 프로젝트 5개는 모두 공개 저장소로 연결됩니다. 코드, 문서와 결과물의 이용 범위는 각 저장소의 `LICENSE.md`에서 확인할 수 있습니다.
