# 1페이지 핵심 보고

보고서는 한 독자와 한 결정에 초점을 맞춘다. 자료에서 독자와 결정이 분명하면 그대로 쓰고, 문장으로 특정하기 어려우면 합리적인 가정을 드러낸다. 이미 결정을 마친 일이라면 후속 검증이나 실행에서 필요한 판단을 첫머리에 둔다.

## 자료에서 근거 고르기

- 확인한 현상과 시험할 가설을 구분한다. 가상 시나리오는 해당 문장에서 가정이라고 표시한다.
- 결정에 필요한 근거를 최대 세 개 고른다. 원문에서 입력, 조건, 판정 기준, 관찰 결과를 확인한다. 수치에는 적용되는 기간, 단위, 비교 기준과 출처를 붙이고 빠진 사실은 [확인]으로 표시한다.
- 구현 여부, 개발 환경의 기능 확인, 운영 효과를 각 근거가 뒷받침하는 수준으로 쓴다. AI가 포함되면 에이전트에 맡긴 작업, 사람이 맡는 판단, 실제로 확인한 출력이나 제한 사례를 밝힌다.

## 한 장에 쓰기

제목은 결정할 업무나 검증 대상을 드러낸다. 기본 순서는 아래와 같다. 조직 양식이 있으면 그 형식을 따른다. 한국어 업무 보고는 짧은 항목과 일관된 종결 표현을 사용하고, 근거 링크는 해당 문단이나 항목 끝에 둔다.

1. **결론과 요청** — 첫 두 문장 안에 권고와 독자가 지금 결정할 일을 적는다.
2. **문제 정의** — 누가 어느 업무에서 무엇을 겪는지, 어떤 원인 가설을 확인하려는지 적는다. 여러 문제는 결정에 중요한 순서로 배치한다.
3. **문제 해결과 검증** — 각 문제에 대응하는 조치와 관찰 결과를 같은 순서로 붙인다. 선택이 필요하고 비교 근거가 있을 때만 대안의 효과, 비용, 위험을 같은 기준으로 짧게 비교한다.
4. **결과 검토** — **사용 제한**에 현재 근거의 적용 범위를 적는다. **앞으로 추진**에 담당 역할, 선행 조건, 실행 순서와 완료 기준을 둔다. 합의된 일정과 담당자만 확정 정보로 쓴다.

구두 브리핑을 요청하면 결론, 가장 중요한 근거, 요청을 담은 30초 분량의 말하기 문안을 별도로 작성한다.

## 최종 확인

- 결론과 요청, 문제와 대응 조치, 결과와 출처가 각각 연결되는지 확인한다. 한 항목에는 한 가지 판단을 담고 소제목과 중복되는 괄호 라벨은 덜어낸다.
- 채팅과 Markdown은 짧은 문단과 목록으로 압축한다. 인쇄용 결과물은 지정 용지, 지정이 없으면 A4로 PDF를 내보낸다. PDF 쪽수와 용지 크기를 확인한 뒤 페이지를 이미지로 열어 줄바꿈, 잘림, 읽기 어려운 글자와 과도한 여백을 점검한다. 넘치면 중복, 부연, 시각 자료부터 덜고 다시 확인한다. 분량을 줄일 때 판단 근거와 적용 조건은 유지한다.
