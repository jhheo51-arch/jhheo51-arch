# OptiMesh | 승인한 변경만 실행하고 되돌리기

[가상 데이터로 데모 열기](https://jhheo51-arch.github.io/jhheo51-arch/optimesh-demo-20261123-v1.html)

가상 항목을 골라 승인하고 결과를 검증한 뒤 복구해 보세요. 각 항목의 원래 값, 제안 값, 현재 값을 나란히 확인할 수 있습니다. 데모는 브라우저에서만 실행됩니다.

## 문제 정의

여러 SaaS를 관리하는 운영 담당자가 설정 문제를 발견하면, 변경할 항목과 현재 값을 확인하고 권한이 있는 사람에게 승인을 받아야 합니다. 변경 후에는 의도한 값이 적용됐는지 확인하고, 되돌릴 때는 그 사이에 다른 사람이 한 변경을 보존해야 합니다.

OptiMesh는 이 과정을 하나의 작업 화면에 담은 운영 시제품입니다. 아래 사례는 2026년 11월 17일 로컬 모의 환경에서 확인한 결과입니다.

## 문제 해결

모의 작업공간에는 정리가 필요한 변경 요청(PR) 2개, 행 수준 접근 통제(RLS) 설정 점검이 필요한 테이블 2개, 담당자가 빠진 문서 1개가 있었습니다.

| 단계 | 운영 담당자가 보는 것 | 시스템이 확인하는 것 |
|---|---|---|
| 1. 변경안 검토 | 진단 항목별로 현재 값과 변경 예정 값을 비교합니다. | 변경안을 승인 대기 상태로 저장합니다. |
| 2. 선택 승인 | 체크박스에서 처리할 항목을 고르고 확인창에서 선택 범위를 검토합니다. | 승인자의 역할과 작업공간 소유권, 선택 항목을 다시 확인한 뒤 선택된 항목의 원래 값을 저장하고 실행합니다. |
| 3. 결과 검증 | 항목별 실행 결과와 재진단 결과를 확인합니다. | 변경한 자원을 다시 읽고 기대한 값과 맞는지 비교합니다. |
| 4. 명시적 복구 | 복구 대상을 검토하고 복구를 확인합니다. | 현재 값을 직전 실행 결과와 비교합니다. 일치하면 저장한 원래 값으로 복구하고 기록을 추가합니다. 다른 변경이 감지되면 덮어쓰기를 보류합니다. |

## 결과 검토

| 검증 사례 | 로컬 모의 환경에서 확인한 결과 |
|---|---|
| 제안 5개 중 3개 승인 | 선택한 3개만 바뀌었고 나머지 2개는 원래 값이 유지됐습니다. 재진단에서 2개 이슈가 남았습니다. |
| 5개 전체 승인 후 복구 | 실행 뒤 재진단에서 이슈가 0개였고, 복구 뒤 5개 자원이 원래 값으로 돌아왔습니다. 실행 기록 5건과 복구 기록 5건이 남았습니다. |
| 승인 권한 확인 | 기획자 역할은 변경안을 검토할 수 있었고, 높은 위험 등급의 RLS 변경 승인은 거절됐습니다. 저장된 자원 상태는 그대로였습니다. |

근거는 2026년 11월 17일 OptiMesh의 로컬 수락 기록입니다. 부분 승인은 로컬 브라우저와 저장 상태를 대조했고, 전체 승인과 복구, 권한 거절은 로컬 서버와 테스트 데이터베이스에서 확인했습니다.

### 사용 제한

검증은 모의 자원과 권한으로 진행했습니다. 실제 SaaS 계정에서의 권한 처리, 동시 변경에 따른 충돌, 운영 환경의 복구 결과는 미검증입니다.

### 앞으로 추진

테스트 계정을 연결할 수 있을 때 읽기 전용으로 먼저 진단합니다. 이후 범위를 제한한 테스트 자원에서 선택 승인과 재조회, 충돌 시 복구 보류를 확인합니다. 승인 범위 밖의 값이 보존되고 실행과 복구 기록이 저장되면 해당 환경의 검증을 완료합니다.
