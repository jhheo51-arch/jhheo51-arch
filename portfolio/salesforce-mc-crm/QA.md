# 포트폴리오 QA 기록

## 문제 정의

채용담당자가 처음 5초에 지원 방향을 파악하고, 끝까지 읽을 때 서로 다른 프로젝트와 결과의 경계를 유지하는지 확인합니다. 자동 검사, 자료 대조와 사람의 읽기 검사는 별개의 결과입니다.

## 읽기 흐름 검토

| 쪽 | 읽는 질문 | 다음 쪽으로 넘기는 근거 |
|---|---|---|
| 1~2 | 어떤 MC, CRM 문제를 다루는 사람인가 | 고객 기록이 다음 행동으로 이어져야 한다는 문제의식 |
| 3~4 | Lead를 저장한 뒤 누구에게 연락할 것인가 | 회사의 시험 Lead 확인과 공개 거래 데이터의 고객군 선정은 서로 다른 자료 |
| 5~6 | 누구를 발송에서 제외하고 오류를 어떻게 확인할 것인가 | MC 과제와 가상 Not Sent 분류의 실행 범위 |
| 7~8 | 차주가 문의하면 어떤 기록과 규칙으로 처리할 것인가 | Aurora의 가상 개발 org와 공개 수용 테스트 |
| 9~10 | 선택적 안내의 효과가 보여도 언제 적용을 보류할 것인가 | 새 합성 A/B 사례와 기존 전자책 및 미구현 도구의 구분 |
| 11 | 어떤 업무를 맡을 수 있는가 | 앞의 세 사례별 확인된 역량과 실제 적용 전 확인 사항 |

6쪽에서 발송 보호 규칙과 7쪽의 상담 규칙을 연결하는 문장을 추가했습니다. 8쪽에서는 Aurora 시연 고객과 9쪽의 합성 고객이 별개임을 밝혔습니다. 10쪽에서는 기존 전자책의 시승 사례와 새 재방문 초안을 분리했습니다. **흐름은 존재합니다.** 다만 실제 채용담당자의 5초 읽기 시험은 하지 않았으므로 이해도까지 검증됐다고 보지 않습니다.

## 주장과 근거

| 본문의 주장 | 근거 종류 | 이번에 확인한 범위 | 사용 제한 |
|---|---|---|---|
| 위플래너 시험 Lead 생성 | 사용자 제공 경험 기록, 공개 PM 포트폴리오 | 공개 서술과 현재 본문 대조 | 내부 Salesforce 기록과 고객 성과는 공개하지 않음 |
| CRM LOOP 고객 666명과 미발송 30% | 공개 거래 분석과 Journey 설계 | 공개 저장소 문서 링크 확인 | 실제 MC 발송과 전환 성과 아님 |
| MC 과제와 Not Sent 분류 | 본인 작성 과제, 로컬 가상 데이터 | 가상 7행 분류 및 자동 검사 4개 | 실제 계정 추출과 QA 아님 |
| Aurora 안전 VOC 기한과 팀장 이관 | 공개 PRD와 README | 개발 org의 수용 테스트 기록 대조 | 실제 상담 기한 준수율 아님 |
| 정기 점검 B-A 방문 완료 +1.09%p | 새 `plan.json`, 합성 고객 원장과 `run.py` | 고객별 적격, 배정, 사건 기간과 계산 재집계 | 교육용 확률에서 나온 합성 수치 |
| 전자책 v0.10, 90쪽과 미구현 도구 | 비공개 A/B Test 상태 문서 | 확인 당시의 저자 검토본과 방향 문서 대조 | 새 정기 점검 사례는 전자책 미반영 |

## 실행한 검사와 하지 않은 검사

| 검사 | 상태 | 판정 범위 |
|---|---|---|
| `qa_portfolio.py` | 실행 완료 | 11쪽 순서, 로컬 링크 20개, 문체, 공개 자료의 기본 개인정보 패턴, 가상 원장과 본문 핵심 수치 |
| `service_revisit_demo/run.py` 재실행 | 실행 완료 | 고정 시드에서 동일 CSV와 결과 JSON, 세 완료 비교 |
| Not Sent 자동 검사 4개 | 실행 완료 | 가상 Reason 분류, 다른 JobID 제외, 중복 및 필수 열 오류 중단 |
| 본문 전체 PDF 이미지 검사 | 미실시 | 현재 텍스트만 있으므로 조판, 글자 잘림과 여백 미확인 |
| 실제 MC Journey 시험 | 미실시 | 계정 접근과 승인된 시험 환경이 없음 |
| 실제 채용담당자 5초 읽기 | 미실시 | 지원 방향과 사례 경계에 대한 사람의 이해 미확인 |
| 새 정기 점검 사례의 저자 검토 | 미실시 | 본인의 판단과 메시지 문구로 확정되지 않음 |

## 사용 제한과 앞으로 추진

자동 검사는 문서와 코드가 서로 일치하는지 확인합니다. 회사 업무의 사실성, 실제 차주의 행동, MC 설정, 저자의 표현과 채용 설득력을 대신 검증하지 않습니다. 먼저 저자가 새 사례와 11쪽 읽기 흐름을 검토하고, 공개 가능한 표현을 확정합니다. 이후 PDF와 웹으로 옮겨 모든 쪽을 이미지로 검사합니다. 실제 MC 계정에 접근할 수 있을 때에는 [MC Journey QA 계획](./MC_JOURNEY_QA.md)의 시험을 별도로 수행하고 기대값과 실제 결과를 기록해야 완료입니다.
