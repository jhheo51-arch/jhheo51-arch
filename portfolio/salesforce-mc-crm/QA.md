# 포트폴리오 QA 기록

## 문제 정의

채용담당자가 처음 5초에 지원 방향을 파악하고, 끝까지 읽을 때 서로 다른 프로젝트와 결과의 경계를 유지하는지 확인합니다. 자동 검사, 자료 대조와 사람의 읽기 검사는 별개의 결과입니다.

## 읽기 흐름 검토

| 쪽 | 읽는 질문 | 다음 쪽으로 넘기는 근거 |
|---|---|---|
| 1~2 | 어떤 MC, CRM 문제를 다루는 사람인가 | 고객 기록이 다음 행동으로 이어져야 한다는 문제의식 |
| 3~4 | Lead를 저장한 뒤 누구에게 연락할 것인가 | 회사의 시험 Lead 확인과 별도 공개 거래 데이터의 고객군 선정은 서로 다른 자료 |
| 5~6 | 신입 지원자로서 어떤 MC 설계와 판단을 보여줄 것인가 | 본인 작성 과제와 별도 가상 Not Sent 분류의 실행 범위 |
| 7~8 | 차주가 문의하면 어떤 기록과 규칙으로 처리할 것인가 | Aurora의 가상 개발 org와 공개 수용 테스트 |
| 9~10 | 선택적 안내의 효과가 보여도 언제 적용을 보류할 것인가 | 새 합성 A/B 사례와 기존 전자책 및 미구현 도구의 구분 |
| 11 | 어떤 업무를 맡을 수 있는가 | 앞의 세 사례별 확인된 역량과 실제 적용 전 확인 사항 |

6쪽에서 발송 보호 규칙과 7쪽의 상담 규칙을 연결하는 문장을 추가했습니다. 8쪽에서는 Aurora 시연 고객과 9쪽의 합성 고객이 별개임을 밝혔습니다. 10쪽에서는 기존 전자책의 시승 사례와 새 재방문 초안을 분리했습니다. **흐름은 존재합니다.** 다만 실제 채용담당자의 5초 읽기 시험은 하지 않았으므로 이해도까지 검증됐다고 보지 않습니다.

## 이전 내부 문안 점검

아래 85점은 v15를 편집 기준으로 자체 점검한 과거 기록입니다. v16의 채용담당자 평가 결과로 옮기지 않습니다. 새 문안은 사람의 5초 독해와 프로젝트 경계 검토 후 다시 평가합니다.

| 항목 | 점수 | 근거 |
|---|---:|---|
| MC 및 CRM 직무 적합성 | 18/20 | Lead, 고객군, 발송 제외와 안전 VOC의 업무 연결이 명확함 |
| 주장별 근거 수준 | 20/25 | 공개 분석과 PRD는 연결됨. 위플래너 내부 매핑, 실제 MC 계정 기록은 없음 |
| 본인 행동과 판단 | 18/20 | 화면 완료 기준, 대상 선정, 예외 처리와 표준 Case 선택의 이유가 있음 |
| 사실과 설계의 경계 | 18/20 | 공개 분석, 계획, 가상 구현, 실제 회사 경험을 구분함 |
| 5초 훑어보기와 문장 밀도 | 11/15 | 표지의 범위는 보이나 11쪽 텍스트는 여전히 길고 실제 독자 시험 전임 |
| **합계** | **85/100** | 내부 편집 점검이며 채용담당자나 자동 필터의 실제 평가 결과가 아님 |

## 사용 제한과 앞으로 추진

자동 검사는 문서와 코드가 서로 일치하는지 확인합니다. 회사 업무의 사실성, 실제 차주의 행동, MC 설정, 저자의 표현과 채용 설득력을 대신 검증하지 않습니다. [전체 항목별 근거](./전체_항목별_근거_20261118_v2.md)와 [개선 체크리스트 v9](./개선_체크리스트_20261118_v9.md)에서 주장별 근거와 남은 일을 구분합니다. 위플래너 필드 매핑과 A/B 전자책 공개 범위, 도구의 실제 구현 상태를 계속 검토합니다. 이후 PDF와 웹으로 옮겨 모든 쪽을 이미지로 검사합니다. 실제 MC 계정에 접근할 수 있을 때에는 [MC Journey QA 계획](./MC_JOURNEY_QA.md)의 시험을 별도로 수행하고 기대값과 실제 결과를 기록해야 완료입니다.
