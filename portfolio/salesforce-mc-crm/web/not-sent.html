Marketing Cloud 미발송 진단

진단 절차 설계와 별도 가상 CSV 예시

Not Sent 진단과 후속 조치 기준을 설계했습니다.

발송 대상보다 실제 발송 건수가 적을 때, 제외를 유지할 건과 다시 확인할 건을 나누는 기준을 설계했습니다.

발송별 고객 키와 미발송 사유를 대조합니다.

가상 CSV 8행 중 같은 발송의 7행을 분류했습니다. 실제 계정 추출이나 발송은 하지 않았습니다.

미발송 사유별 판단 기준

  • 제외 유지수신거부와 보호 정책에 따른 제외는 그대로 둡니다.
  • 오류 확인주소와 콘텐츠를 점검한 뒤 발송 자격을 다시 확인합니다.
  • 판단 보류알 수 없는 사유는 담당자가 확인할 때까지 보류합니다.
가상 입력 8행 중 대상 발송 7행의 분류 결과
가상 키미발송 사유분류
T01Held보호 유지
T02Unsubscribed Master보호 유지
T03Account Level Opt Out보호 유지
T04List Detective Exclusion원천 확인
T05Build Email Error or Send Failure콘텐츠 확인
T06Domain Exclusion보호 유지
T07Unexpected Account Policy사람 확인

보호 유지 4건, 원천 확인 1건, 콘텐츠 확인 1건, 담당자 확인 1건입니다. 자동 재발송은 0건입니다. T07은 알 수 없는 사유의 처리 경로를 확인하기 위해 만든 값입니다. 검증 범위는 가상 데이터의 로컬 분류이며, 계정에서 추출하거나 발송한 기록은 없습니다.

관련 질문

열람률의 한계를 고려해 어떤 지표를 제안했나요?

Apple Mail Privacy Protection으로 열람률이 부풀 수 있어 클릭률과 링크 정상 동작을 먼저 확인하도록 제안했습니다. 예약이나 방문을 추적할 수 있을 때는 해당 행동 지표로 효과를 판단합니다.

Salesforce 지표 안내 ↗
Not Sent는 원인별로 어떻게 처리했나요?

가상 CSV에서 JobID로 같은 발송을 고르고 SubscriberKey와 Reason으로 보호 제외, 원천 오류, 콘텐츠 오류, 담당자 확인을 구분했습니다. 별도 가상 입력 8행 중 대상 발송 7행을 분류한 결과는 보호 유지 4건, 원천, 콘텐츠, 사람 확인 각 1건, 자동 재발송 0건이었습니다. 실제 계정 발송 결과가 아닙니다.

Not Sent 추출 안내 ↗
감사 로그는 어떻게 보관하도록 제안했나요?

장기 조회가 필요하면 Audit Trail의 계정별 보관 기간을 확인하고 정기 추출과 외부 보관을 계획합니다. SFTP도 영구 보관소로 보지 않고, 파일 건수, 자동화 실패 알림, 시간대, 조회 권한을 함께 확인합니다. 실제 적용 시 최신 정책과 계정 조건을 재확인해야 합니다.

Audit Trail 공식 안내 ↗
장기 비활동 고객을 삭제 후보로 어떻게 검토했나요?

Contact Key 통일, 보호 대상 제외, 삭제 후보를 나누는 2단계 SQL 초안을 썼습니다. 재검토에서는 최근 7일 기록과 365일 비활동 비교의 기간 불일치를 바로잡았습니다. 공식 안내상 일반적인 Data View 조회 범위는 최근 180일입니다. 365일 비활동을 판단하려면 별도 보관 이력과 원천 시스템을 대조한 뒤 삭제 승인을 받도록 설계했습니다.
