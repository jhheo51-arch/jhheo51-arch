# Salesforce MC 및 CRM 포트폴리오 마스터 텍스트

## 문제와 대상

채용담당자와 MC, CRM 실무자가 회사에서 확인한 일, 공개 데이터 분석, 가상 Salesforce 구현, 합성 실습을 구분해 읽을 수 있도록 정리한 마스터 문안입니다. 특정 회사에 제출한 맞춤본이나 완성 PDF가 아닙니다.

## 읽는 순서

[포트폴리오 본문 v15](./허재혁_MC_CRM_포트폴리오_본문_20261118_v15.md)을 먼저 읽습니다. 1~2쪽은 지원 방향과 경력의 문제의식, 3~6쪽은 Lead 수집에서 캠페인 대상과 발송 운영, 7~8쪽은 차주 상담과 안전 VOC 규칙, 9~10쪽은 선택적 서비스 재방문 실험의 판단과 전자책, 11쪽은 맡을 수 있는 업무입니다. 9~10쪽의 A/B 사례는 전자책과 도구가 완성될 때까지 추가 논의를 멈췄습니다.

## 실행과 확인

Python 3.10 이상에서 다음을 실행합니다. 외부 패키지는 필요하지 않습니다.

```sh
python portfolio/salesforce-mc-crm/service_revisit_demo/run.py
python portfolio/salesforce-mc-crm/qa_portfolio.py
cd portfolio/salesforce-mc-crm/not_sent_demo
python -m unittest -v test_not_sent_review.py
```

첫 두 명령은 저장소 루트에서 실행합니다. `cd`로 폴더를 옮긴 뒤 마지막 명령으로 가상 MC 발송 제외 사례를 검사합니다.

## 자료 범위와 사용 제한

위플래너의 시험 Lead 생성은 사용자 경험 기록과 [공개 PM 포트폴리오](../../허재혁_포트폴리오_PM.pdf)를 근거로 합니다. [CRM LOOP](https://github.com/jhheo51-arch/crm-loop)와 [Aurora Owners 360](https://github.com/jhheo51-arch/aurora-owners-360)은 각각 공개 저장소에서 설계와 구현 범위를 확인할 수 있습니다. A/B Test 전자책 v0.10은 비공개 저자 검토본이며 시승 안내를 관통 사례로 사용합니다. 이 폴더의 정기 점검 사례는 별도로 생성한 **AI 협업 합성 실습 초안**입니다. 실제 OEM 고객 자료, MC 발송, 서비스센터 성과 또는 완성된 A/B 제품이 아닙니다.

로컬 코드 검사가 통과해도 실제 독자의 이해, 현장 효과, MC Journey 설정과 발송 QA가 끝난 것은 아닙니다. [본인 검토표 v3](./본인_검토_20261118_v3.md)에 선택한 여섯 방향과 현장에서 확인할 항목을 나눴습니다. [면접 설명 준비 v3](./면접_설명_준비_20261118_v3.md)는 그 선택을 반영한 연습용 대본입니다. 현재 폴더에는 PDF와 웹 디자인 결과물이 없습니다.

## 앞으로 추진

먼저 [비 A/B 항목별 근거](./비AB_항목별_근거_20261118_v1.md)에 적은 위플래너의 공개 가능한 매핑 흔적과 MC 과제 발췌본을 검토합니다. A/B 사례의 추가 논의는 전자책과 도구가 완성된 뒤에 이어갑니다. 그다음 이 마스터 텍스트를 PDF와 웹 원본으로 조판하고 모든 쪽의 잘림과 여백을 확인합니다. 실제 MC 계정 접근이 허용되면 `MC_JOURNEY_QA.md`의 시험 데이터를 사용해 분기, 제외, 기간과 결과 연계를 검증합니다. 공개 저장소에 있다고 실제 고객 캠페인의 결과로 해석하지 않습니다.
